# 08 · 智能体市场：把 LobeChat 的 505 个智能体搬进来

## 一句话

`lobehub/lobe-chat-agents`（MIT）里有 505 个现成的人格提示词，全部导进 LibreChat 的市场，
头像用 DiceBear 本地生成，用户自建的智能体默认私有、彼此不可见。

## 1. 市场在哪、由什么决定

LibreChat 的市场页是 **`/agents`**（不是 `/marketplace`，那个路径 404）。
页面结构：顶部搜索 + 7 个分类 tab + 「全部」；卡片来自 `GET /api/agents?requiredPermission=1&limit=...`。

分类是**写死在前端的 7 个**，不是数据库里配的：

| value | 中文 |
|---|---|
| `general` | 通用 |
| `hr` | 人事 |
| `rd` | 研发 |
| `it` | IT |
| `finance` | 财务 |
| `sales` | 销售 |
| `aftersales` | 售后 |

`categories` 集合是空的，`/api/categories` 返回的是另一套旧枚举（idea/travel/...），
**跟市场 tab 无关**，别被它误导。

## 2. 导入：怎么跑

```bash
# 服务器上
cd /tmp && curl -sL https://codeload.github.com/lobehub/lobe-chat-agents/tar.gz/refs/heads/main -o a.tgz
tar -xzf a.tgz
python3 /tmp/import-lobe-agents.py --dry-run   # 先看分类分布
python3 /tmp/import-lobe-agents.py             # 真跑，约 8 分钟
```

脚本在 `scripts/import-lobe-agents.py`，四步：

1. **读 JSON**：`src/*.json`，同一个 identifier 有 `zh-CN` / `en-GB` / 无后缀多个版本，
   优先级 `zh-CN > zh > 默认`。180 个英文文件正好是没有中文版的那批。
2. **头像**：LobeChat 的 `meta.avatar` 有 484 个是 emoji（📝🥥），LibreChat 的头像只吃图片，
   所以统一换成 DiceBear `bottts-neutral`（机器人脸，比人像更"像个智能体"），
   seed 用 identifier —— 同一个人每次都同一张脸。
   **SVG 是下载到本地再发的**（`/opt/umf/deploy/web/app/avatars/lobe/`），
   不让浏览器去连 `api.dicebear.com`：国内访问那个域不稳，且多 505 个外部请求。
3. **分类映射**：LobeChat 的 14 类 → LibreChat 的 7 类，`programming/design → rd`、
   `career → hr`、`marketing → sales`、其余 → `general`；
   再用关键词把 LobeChat 没有的 `finance` / `it` / `aftersales` 捞出来。
4. **建卡 + 授权**，见下。

## 3. 两个必须知道的坑

### 坑一：公开要走 ACL，而且用的是 `_id` 不是 `id`

`POST /api/agents` 建出来的卡默认只有作者能看见（`isPublic` 根本不参与，走的是 ACL）。
要让它出现在所有人的市场里，得再发一次：

```http
PUT /api/permissions/agent/{_id}
{"public": true, "publicAccessRoleId": "agent_viewer", "updated": [], "removed": []}
```

`{_id}` 是 Mongo 的 `6afe...`，不是 `agent_xxx`。传 `agent_xxx` 会返回
`404 Resource not found`，看起来像接口不存在，其实是 id 形式不对。

### 坑二：自定义端点缺 `endpointType` 会把聊天整条打断

现象：网页里发消息一直转圈，对方不回复；`/app/api/logs/error-*.log` 里是

```
Error: Unknown endpoint: Brain
  at parseCompactConvo (packages/data-provider/dist/index.js:1045)
  at buildEndpointOption (api/server/middleware/buildEndpointOption.js)
```

根因：`parseCompactConvo({ endpoint, endpointType })` 里，
`compactEndpointSchemas` 只认 `openAI / custom / google / agents ...` 这些内置 key。
我们端点叫 `Brain`，只能靠 `endpointType: 'custom'` 兜底；
而客户端的某些路径（新会话首条消息尤其明显）不带这个字段 → 直接抛错。

试过把端点改名成 `custom`：配置校验直接拒绝
（`Value cannot be one of the default endpoint (EModelEndpoint) values`），这条路不通。

最终修法是给中间件打一个 4 行的补丁，缺 `endpointType` 时按配置里的 `type` 补上：

```js
if (!endpointType && endpointsConfig?.[endpoint]?.type) {
  endpointType = endpointsConfig[endpoint].type;
  req.body.endpointType = endpointType;
}
```

落地方式：`deploy/patches/buildEndpointOption.js` 通过 compose 单文件挂载覆盖进容器。
**换镜像后要重新生成**（从新镜像里 `docker cp` 出来再打补丁），否则文件对不上会启动报错。

## 4. 用户隔离：默认就是隔离的，不用另写代码

LibreChat 用 ACL + 角色权限，`USER` 角色的默认值刚好满足需求：

```
AGENTS:  { USE: true, CREATE: true, SHARE: false, SHARE_PUBLIC: false }
```

- `CREATE: true` → 朋友能自己建智能体，写名字、描述、角色提示词、传头像（原生支持）
- `SHARE: false` → 不能分享给指定人
- `SHARE_PUBLIC: false` → 不能挂到市场（实测 `PUT /api/permissions/...` 返回 403）

实测（两个临时账号）：

| | 建自己的 | 看到自己的 | 看到别人的私有 | 看到市场的 505 个 |
|---|---|---|---|---|
| 朋友 A | ✅ | ✅ | ❌ | ✅ |
| 朋友 B | ✅ | ✅ | ❌ | ✅ |
| 管理员 | ✅ | ✅ | ✅（管理员可见全部） | ✅ |

唯一要改的是 `MARKETPLACE.USE`：默认 `false`，不改的话普通用户根本进不去市场页。

```bash
PUT /api/roles/USER/marketplace   {"permissions": {"USE": true}}
```

## 5. 顺手修掉的一个路由遮蔽

`Caddyfile` 原来把整个 `/api/admin/*` 转给 brain，导致 LibreChat 自己的管理接口
（`/api/admin/roles`、`/api/admin/users`）全部 404。现在只转厂商配置这一支：

```
handle /api/admin/providers* {
    reverse_proxy brain:8000
}
```
