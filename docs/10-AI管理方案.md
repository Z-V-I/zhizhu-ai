# AI 管理：IMA 知识库接入

> 用户要求：「把我们的数据库（全量，含用户数据、运维数据）传进 ima 知识库（使用 apikey）、
> 然后要查询时使用 apikey 问 ima 得到回答。」「我想要使用 ima 的生态。」

已实现。这一页只讲**怎么实现的、要填什么、边界在哪**。

## 一、接口事实（2026-11 核实）

```
Base URL : https://ima.qq.com
路径前缀 : /openapi/wiki/v1
方法     : 全部 POST + JSON body
认证     : Header  ima-openapi-clientid / ima-openapi-apikey
返回     : {"retcode":0,"errmsg":"成功","data":{...}}   （老文档写 code，两种都兼容）
```

凭证在 **https://ima.qq.com/agent-interface** 获取（ClientID + APIKey）。

用到的端点：

| 端点 | 用途 |
|---|---|
| `search_knowledge_base` | 列出可写知识库（limit ≤ 20，超了报 51） |
| `create_media` | 申请 media + 拿 COS 临时凭据 |
| COS PUT | 自己算 V5 签名把字节传上去 |
| `add_knowledge` | 登记进知识库 |
| `search_knowledge` | 在知识库里检索 |
| `get_media_info` | 拿条目直链 / notebook_id |
| `get_doc_content` | 读笔记正文 |

**投放一个文件是四步，不能省**：create_media → COS PUT → add_knowledge。
`import_doc`（建笔记）不需要 COS，但笔记不进知识库，所以灌数据仍走文件上传。

## 二、传什么（这才是关键）

不传 SQL dump。`pg_dump` 出来的东西检索到的是几百行 INSERT，
问"这个人最近在忙什么"它答不出来。按"一问一答用得上"的单位切：

| 文档 | 内容 | 能回答 |
|---|---|---|
| `站点总览.md` | 规模统计、近 30 天登录（含失败）、整理任务、导入批次、模型配置 | 「站点最近怎么样」「有没有登录异常」 |
| `用户档案-<id>.md` | 画像五组、长期记忆（按层）、话题、活跃月份、登录记录、**他本人更正过的内容**、站内评价 | 「这个人最近在忙什么」「他的偏好是什么」 |

单文档超过 60KB 会截断，避免"命中但读不完"。

每个用户一份档案的上限是 50 人（按记忆条数取前 50）；其余走"只同步某一个人"。

## 三、问 IMA 是怎么问的

```python
hits = await ima.search(kb_id, question, limit=6)         # IMA 侧检索
for h in hits: body = await ima.read_entry(h["media_id"]) # IMA 侧取内容
answer = await llm.complete(..., blocks + question)       # 组织成人话
```

**说明**：IMA OpenAPI 提供的是**检索**，没有对话/补全端点。
所以"问 IMA 得到回答"在 API 层就是：检索在 IMA 完成、内容从 IMA 取回、
最后一步由模型把资料说成人话 —— 这正是 IMA 界面里它在做的事。
检索和资料都在 IMA 侧，不是我们另建了一层索引。

答案下面会列出"依据（来自 IMA 检索）"，写清命中了哪几份文档。

## 四、要填什么

服务器 `/opt/umf/deploy/.env` 加两行，然后重启 brain：

```bash
IMA_CLIENT_ID=你的ClientID
IMA_API_KEY=你的APIKey
```

```bash
cd /opt/umf/deploy && docker compose -f docker-compose.lite.yml up -d brain
```

填完后打开 `/console#/ai`：
1. 知识库下拉里会出现你的知识库（如果为空，先去 IMA 客户端建一个）
2. 「开始同步」→ 看到进度 → 完成后下方列表逐份显示"已上传/失败+原因"
3. 在「问 IMA」里提问

## 五、幂等

`ima_sync_state` 表记 `doc_key + content_hash + media_id`。
内容哈希没变就跳过 —— IMA 没有"更新文档"接口，每次都是新上传一份，
不跳过的话知识库里会堆满同名文件，检索结果全是重复。

想强制重传就勾「强制重传」。

## 六、已知边界

- **单文件上限**：create_media 有大小限制（IMA 侧），超了会报错并在列表里标红。
- **删除**：API 没提供删条目接口，重传只会新增。清理得去 IMA 客户端手动做。
- **检索质量**：取决于 IMA 自己的切分与召回，我们无法调节，也不该调节
  （调了就变成"自建 RAG"，与用户的诉求相反）。
- **凭证轮换**：改 `.env` 后需重启 brain；界面不留明文存储。
