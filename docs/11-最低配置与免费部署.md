# 最低服务器要求与免费部署评估

> 结论先说：**实测常驻峰值 1.3 GB，2C4G 是稳妥的底线，2C2G 要调参且没有余量；真正零成本的只有 Oracle Cloud 的 Always Free ARM。**
> 本文所有数字都是 2026-11-22 在线上机（阿里云香港 2C4G）上量的，不是估算。

---

## 1. 实测：内存到底被谁吃了

5 个容器，`memory.peak`（含启动峰值，容器已跑 3 天）与 `docker stats` 采样：

| 容器 | 常驻 | 峰值 | 当前 limit | 说明 |
|---|---|---|---|---|
| `api`（LibreChat，Node） | 459 MB | **537 MB** | 768 MB | 大头。Node 堆随对话长度、附件解析上涨 |
| `mongodb` | 313 MB | **512 MB** | 512 MB | **已经顶到 limit**（WiredTiger 缓存 256 MB + 连接开销） |
| `postgres`（+pgvector） | 60 MB | 117 MB | 384 MB | 冷启动建 schema 时才高 |
| `caddy` | 48 MB | 64 MB | 128 MB | 静态文件 + 反代 |
| `brain`（FastAPI） | 62 MB | 72 MB | 384 MB | 记忆注入、IMA、后台接口全在这 |
| **容器合计** | **942 MB** | **1302 MB** | 2176 MB | |
| Docker + 系统 | ~300 MB | — | — | `free` 显示 used 1578 MB，与上表吻合 |

CPU：`load average 0.10 / 0.03 / 0.01`。SSE 流式几乎不烧 CPU，
**核数不是给聊天用的，是给"镜像拉取 + brain 构建"用的**。

磁盘（`docker system df`）：

| 项 | 占用 |
|---|---|
| 镜像 | 9.2 GB（其中 4.3 GB 的 `librechat-dev` 只在抽取静态文件时用得到，之后可删） |
| 数据卷 | 641 MB（mongo 364 + 图片 168 + pg 68 + caddy 14） |
| 构建缓存 | 801 MB（可清） |
| 系统 | ~2 GB |

## 2. 三档配置

| 档 | 配置 | 能否跑住 | 月成本 |
|---|---|---|---|
| **硬底线** | 1C2G + 2 GB swap | 能跑，但要按 §3 调参；单人低频使用可以，两人同时传文件会抖 | ¥30–50 |
| **建议最低** | **2C2G + 2 GB swap** | 调参后稳定，留 400 MB 余量 | ¥40–70 |
| **舒适（当前）** | **2C4G / 40 GB** | 峰值 1.3 G，余量 2.7 G，不用调任何参数 | ¥60–120 |
| 宽裕 | 4C8G | 只有"在这台机器上构建镜像/跑 torch 压缩"时才需要 | ¥150+ |

**1C1G 不要试**：单是 LibreChat 一个容器峰值就 537 MB。

### §3 如果只能上 2 GB，必须改这两处

```yaml
# docker-compose.lite.yml
mongodb:
  command: ["mongod", "--wiredTigerCacheSizeGB", "0.1"]   # 256MB → 100MB，省 150MB
  mem_limit: 384m
api:
  mem_limit: 640m     # 从 768 降下来，真 OOM 时只杀它一个，不拖垮整机
```

再加 2 GB swap（`fallocate -l 2G /swapfile`）。swap 只是防 OOM 的保险，
不是性能来源——Node 一旦被换出去，回复会明显变慢。

## 4. 免费部署：三条路，只有一条真的免费

### ✅ 路线 A：Oracle Cloud Always Free（唯一推荐的零成本方案）

| 项 | 额度 |
|---|---|
| 计算 | `VM.Standard.A1.Flex`，**4 OCPU / 24 GB ARM**（Ampere），永久免费 |
| 存储 | 200 GB 块存储 |
| 流量 | 10 TB/月出站 |
| 期限 | 无（不是 12 个月试用） |

**这个额度跑本栈是碾压级的**：峰值 1.3 G，24 G 内存用不到 6%；
顺手还能开个 Ollama 跑本地小模型。区域选 `ap-tokyo-1` / `ap-osaka-1` / `ap-singapore-1`，
国内访问比欧美好；不如香港，但免费。

**已核对：本栈所有镜像都有 arm64 版本**，不用改任何东西就能在 ARM 上跑。

| 镜像 | arm64 |
|---|---|
| `ghcr.io/danny-avila/librechat-dev-api` | ✅ |
| `ghcr.io/danny-avila/librechat-dev`（仅抽静态用） | ✅ |
| `mongo:7` | ✅ |
| `pgvector/pgvector:pg16` | ✅ |
| `caddy:2-alpine` | ✅ |
| `brain`（`python:3.12-slim` 构建） | ✅ 现场构建即可 |

**已知的坑（提前说，免得白折腾）**：

1. **注册要真实信用卡**（验证身份，扣 1 美元后退回），虚拟卡/预付卡不行。
2. **A1 常年"Out of capacity"**。三个办法：换可用域（AD-1/2/3）、
   先开 1 OCPU/6 GB 再慢慢扩、或者把账户升级成 Pay As You Go
   （免费额度不变，只是排队优先级变高——**开了预算告警再升**）。
3. **Home Region 选定不能改**，注册时就选日本/新加坡。
4. ARM 上 `docker compose build brain` 要 3–5 分钟（pip 装 asyncpg/psycopg 要编译），
   一次性成本。

**迁移成本**：把 `deploy/` 目录 scp 过去，`docker compose -f docker-compose.lite.yml up -d`，
再把 `.env`、`deploy/web/app`（静态文件）、三个数据卷搬过去。
数据量小（641 MB），`docker run --rm -v ... tar` 打包传即可，半小时的事。

### ⚠️ 路线 B：家宽 + Cloudflare Tunnel（零月费，但有隐性成本）

仓库里已经有 `deploy/docker-compose.tunnel.yml`，就是为这个场景写的：
不开放 80/443，由 `cloudflared` 主动外连，CF 边缘终结 TLS。

- 需要一台**常年开着**的机器：旧笔记本 / NAS / 迷你主机 / 软路由（x86 或 ARM 都行）。
- 电费：一台 15 W 的迷你主机 ≈ ¥8/月；旧笔记本 45 W ≈ ¥25/月。
- 风险：断电、断网、系统更新重启 = 站挂了，而且你不在家时没法救。
- 家宽上行通常 30–100 Mbps，够 20 人聊天（SSE 只占几 KB/s）。
- **国内家宽做网站需要注意运营商条款**（个人宽带通常禁止对外提供 Web 服务），
  只给自己和朋友用一般没人管，但别公开宣传。

### ❌ 路线 C：免费 PaaS（Render / Koyeb / Railway / Fly）—— 都不合适

2026 年 11 月的实际额度：

| 平台 | 免费额度 | 为什么不合适 |
|---|---|---|
| Render | 512 MB / 750 小时，15 分钟无流量休眠，**免费实例不能挂持久盘**，免费 PG 30 天过期 | 512 MB < 单个 api 峰值 537 MB；没盘 = 每次重启数据没了 |
| Koyeb | 1 个 web service，512 MB / 0.1 vCPU，2 GB SSD，1 小时空闲缩容到零 | 同上，且 0.1 vCPU 跑 Node 会很慢 |
| Railway | $5 一次性试用，之后 $1/月额度，服务上限 0.5 GB | 额度不够常驻；$1/月撑不住 |
| Fly.io | **已取消免费层**，只剩 $1 / 7 天试用 | — |
| Heroku | 2022 年就取消免费层 | — |

核心矛盾：**这套栈是"5 个常驻进程 + 2 个数据库 + SSE 长连接 + 持久盘"**，
而免费 PaaS 的设计前提是"一个无状态小容器、可以随时休眠"。
硬塞进去只会得到一个每次冷启动 1 分钟、数据随时丢的东西。

**唯一可能的变体**：数据库外置（MongoDB Atlas M0 免费 512 MB + Neon 免费 PG 0.5 GB），
机器上只跑 api + brain + caddy（≈ 670 MB），这样 Koyeb 的 512 MB 还是不够、1 GB 的机器可以。
但 Atlas M0 的 512 MB **已经接近当前 364 MB 的数据量**，再涨就写不进去了。
省下的钱不值得这笔复杂度，除非你只是想验证一下。

## 5. 建议

1. **现在这台 2C4G 就是"推荐最低"**，不用升级，也不用降级——已经是性价比最优解。
2. 想彻底零成本、且能接受注册折腾：**开一台 Oracle A1（2 OCPU / 12 GB 就够，留 2 核给别的）**，
   把 `deploy/` 整个搬过去，本栈原样跑。
3. 短期省钱：2C2G 也能跑，但要按 §3 调 mongo 缓存和 api limit，并加 swap。
4. 顺手能省 4 GB 磁盘：静态文件抽完之后 `docker rmi ghcr.io/danny-avila/librechat-dev:latest`。
