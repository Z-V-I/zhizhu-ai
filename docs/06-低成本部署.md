# 低成本部署：阿里云新加坡 2C4G

> 目标：**¥50–100/月跑全栈**，8 家模型可切换，PWA 能装到手机主屏，记忆和导出都在。
> 做法：砍掉四个"常驻占内存但个人用不上"的组件，并且**完全不构建前端**。

---

## 1. 砍了什么，为什么能砍

| 砍掉 | 省下 | 你失去什么 | 为什么无所谓 |
|---|---|---|---|
| **LiteLLM** | 350–500 MB + 一个容器 | 额度、日志、按 key 计费、管理后台 | 你不出售，这些一个都用不上。**模型别名、密钥、参数修正、兜底链**搬进 `brain/app/upstream.py`，150 行 |
| **Redis** | ~50 MB | 缓存、限流、多实例会话共享 | 单机单实例，LibreChat `USE_REDIS=false` 官方支持 |
| **Meilisearch** | 150–300 MB | 会话全文搜索的高亮和相关度排序 | 20 人的会话量，Mongo 自带查询够用 |
| **Triton/torch（LLMLingua-2）** | 900 MB–1.2 GB | "粘贴 20 页文档"时的 token 级压缩 | 滚动摘要承担主力压缩，那个不需要模型 |

**关键一条：前端不构建。** LibreChat 用官方镜像，PWA 靠"从镜像里抽出 `index.html`、插 6 行、再挂载回去"实现（见 §4）。这一步把 30 分钟、2 GB 内存峰值的构建，换成 10 秒、0 峰值。

---

## 2. 内存账本（实测）

2026-11-19 在阿里云新加坡 2C4G（Debian 12）实跑，`docker stats` 真实读数：

| 容器 | 预估 | **实测** |
|---|---|---|
| caddy | 20–30 MB | **66 MB** |
| api（LibreChat 后端） | 300–450 MB | **296 MB** |
| brain（FastAPI） | 120–200 MB | **38 MB** |
| mongodb（cache 限 256 MB） | 250–350 MB | **138 MB** |
| postgres（shared_buffers 128 MB） | 60–120 MB | **62 MB** |
| client（静态 nginx） | 30–60 MB | **已删除**（改由 caddy 直接发） |
| **合计** | 0.8–1.2 GB | **600 MB** |

比预估低很多，原因有三个：`mem_limit` 是按上限设的，实际用不到；brain 没装 torch；静态文件不占进程。

**结论：2 GB 内存就能跑**，4 GB 是给构建、备份和突发留的余量。系统 + Docker 自身约 250 MB，全部加起来不到 900 MB。

磁盘：镜像约 3 GB，数据 + 日志一年 3–5 GB。**60 GB ESSD 够三年**。

## 3. 阿里云开机器

1. **产品**：轻量应用服务器（不是 ECS，轻量更便宜且自带流量包）
2. **地域**：**新加坡**。不要选国内地域——国内机房出站到 OpenAI / Gemini / Grok 不通，且 80/443 需要备案
3. **配置**：2 核 4 GB，系统镜像 Debian 12 / Ubuntu 22.04 都行（实测这台是 Debian 12 bookworm），磁盘 40 GB 起
4. **防火墙**：控制台 → 防火墙 → 放行 **22 / 80 / 443**（默认只开 22，这一步不做会一直 502）
5. **域名**：A 记录指向公网 IP。**DNS 用灰云（不开 CF 代理）** —— CF 代理会缓冲 SSE，打字机效果会变成"憋一大段再吐出来"
6. **证书**：不用手配，Caddy 自动申请 Let's Encrypt，前提是 80/443 通、域名已解析

> 为什么新加坡而不是香港：OpenAI 和 Gemini 的 API 都不把中国香港列为可用区域，会被 IP 拦。新加坡和日本都全通，新加坡到国内 70–110 ms，可用。

## 4. 部署（五条命令）

```bash
# ① 装 Docker（Debian/Ubuntu 通用）
curl -fsSL https://get.docker.com | sh

# ② 拿代码（部署后实测走的是上传 tar 包，有仓库就 git clone）
tar xzf umf.tgz -C /opt/umf && cd /opt/umf/deploy

# ③ 填配置（每一项都有注释，至少要填 DOMAIN 和 5 个密钥）
cp .env.example .env && vi .env

# ④ 抽取已编译的前端产物（31 MB，30 秒，不构建）
../scripts/extract-static.sh

# ⑤ 起
docker compose -f docker-compose.lite.yml up -d --build
```

四件事**不要**做，做了反而会坏：

1. **不要 `npm install` / `pnpm build`** —— 2C4G 构建峰值 2 GB，会被 OOM killer 干掉；而且镜像里已经有编译好的产物
2. **不要单独跑 client 容器** —— `librechat-dev` 镜像的 CMD 是 `npm run backend`，里面**没有静态服务器**，起了也不发页面
3. **不要用 CF 橙云代理** —— 会缓冲 SSE
4. **不要把 `ALLOW_REGISTRATION` 长期开着**

`.env` 里必须自己生成的四项：

```bash
openssl rand -hex 32   # JWT_SECRET
openssl rand -hex 32   # CREDS_KEY   （必须是 64 位 hex）
openssl rand -hex 16   # CREDS_IV    （必须是 32 位 hex）
openssl rand -hex 32   # JWT_REFRESH_SECRET
```

开第一个账号（**没有命令行建号工具**，LibreChat 不提供 `create-user`）：

```bash
# 1. 临时开注册
sed -i 's/^ALLOW_REGISTRATION=.*/ALLOW_REGISTRATION=true/' .env
docker compose -f docker-compose.lite.yml up -d api

# 2. 打开站点注册，或直接打接口
curl -X POST https://你的域名/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"你@邮箱","password":"密码","confirm_password":"密码","name":"昵称","username":"账号"}'

# 3. 立刻关回去
sed -i 's/^ALLOW_REGISTRATION=.*/ALLOW_REGISTRATION=false/' .env
docker compose -f docker-compose.lite.yml up -d api
```

> 注册接口返回 "Please check your email to verify" 是模板文案，没配 SMTP 时**不会真的发信**，账号立即可登录。别被它误导。

### PWA 是怎么"零构建"做出来的

`extract-static.sh` 干了三件事：

```
docker create 官方镜像  →  docker cp 出整个 /app/client/dist（31 MB / 290 个文件）
                      →  改 index.html：主题色、<title>UMF、摘掉镜像自带的 manifest 链接
                      →  插我方 manifest + apple-touch-icon + Service Worker 注册
```

产物落在 `deploy/web/app/`，由 **caddy 直接托管**（`try_files {path} /index.html` 做前端路由回退），所以不需要 client 容器。

**升级镜像后要重跑一次脚本**，否则 `index.html` 里的 JS 哈希名和新镜像对不上，页面白屏。脚本是幂等的，靠 `umf-pwa-injected` 这个标记判断，重复跑不会插两遍。

## 5. 模型：先只配国内 5 家

`deploy/brain/models.json` 里已经写好了 8 家。**填了哪家的 Key，就只有哪家启用**，没填的别名自动跳过、不影响启动——所以你完全可以先只买 DeepSeek + 通义，跑通了再加。

最小可用集（够聊天 + 够抽取 + 够向量）：

```env
DEEPSEEK_API_KEY=...   # 主力对话，便宜
DASHSCOPE_API_KEY=...  # 通义：抽取用小模型 + text-embedding-v3 向量
```

三件事要记住：

1. **向量维度是 1024**（`schema.sql` 里写死）。换 embedding 供应商必须同时改表和 `models.json` 的 `dimensions`，否则插入直接报维度不匹配。
2. **模型名会过期**。`models.json` 里的名字是 2026-11 的值，报 `model not found` 时先去厂商文档核对，改这个文件就行，不用动代码。
3. **缺 Key 不是错误**，是"这家没启用"。启动日志里会有一行 `alias xxx disabled: XXX_API_KEY not set`，正常。

## 6. 出问题先看这五个

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面 502 | 安全组没放行 80/443，或 Caddy 还没拿到证书 | `docker compose logs caddy` 看 ACME 报错 |
| 打开是白屏 | `index.html` 是从旧镜像抽的，和新镜像的 JS 哈希名对不上 | 重跑 `scripts/extract-static.sh` |
| 打字机效果"憋一大段" | 中间有代理在缓冲 SSE | 确认 DNS 是灰云；`Caddyfile` 里 `flush_interval -1` 必须在 |
| 回复正常但记不住 | 抽取失败或没有 Key | `docker compose logs brain \| grep extract`；确认 `DASHSCOPE_API_KEY` 有值 |
| 容器反复重启 | 内存不足被 OOM | `dmesg \| grep -i kill`；把 mongo 的 `wiredTigerCacheSizeGB` 再降到 0.2 |
| 插入记忆报维度错误 | embedding 维度和表不一致 | 见 §5 第 1 条 |
| 模型列表里少几个 | 那家 Key 没填，brain 会跳过该别名 | 这是设计行为，不是 bug |
| 定时任务写入返回 503 | 单副本没声明 | 确认 `SCHEDULES_SINGLE_PROCESS=true` 在 api 的环境变量里 |

资源占用随时看：

```bash
docker stats --no-stream
```

## 7. 这台机器之后要不要换

不需要换。这套栈的瓶颈是**内存**，不是 CPU 也不是带宽：

- 20 个朋友、并发 3–5 个流式对话，2 核完全够（SSE 是 IO 等待，不吃 CPU）
- 真正的增长点是记忆条数。一万条以内，Postgres + 1024 维 HNSW 在 4 GB 机器上毫秒级返回
- 什么时候该升级：同时在线超过 15 人，或想开 LLMLingua / 本地 embedding。那时换 8 GB，别换核数

**钱花在哪比花多少重要**：这台机器一个月 ¥50–100，而模型调用如果不管上下文膨胀，一个月能烧掉 ¥300。所以 `HISTORY_BUDGET_TOKENS=8000` 和 8 轮滚动摘要不是体验参数，是省钱开关，别为了"记得更多"把它调到 4 万。

## 8. 首次部署实录（2026-11-19）

真机：阿里云新加坡 `203.0.113.10`，Debian 12，2 核 / 3.5 GB 可用 / 45 GB，域名 `chat.example.com`。

**跑通了什么（有返回值，不是"应该能行"）**

| 项 | 实测结果 |
|---|---|
| Let's Encrypt 证书 | `certificate obtained successfully`，tls-alpn-01 验证通过 |
| 首页 | `200`，`<title>UMF</title>`，`umf-pwa-injected` 标记存在 |
| `/manifest.webmanifest` | `200` |
| `/sw.js` / `/icons/icon-192.png` | `200`，MIME 正确 |
| brain 健康检查 | `{"ok":true,"service":"brain"}` |
| Postgres 建表 | `brain.db schema ready`（8 张表 + pgvector 扩展） |
| LibreChat 加载配置 | 无 `Outdated Config version` 告警，5 个 modelSpecs 生效 |
| 模型透出 | `Brain -> 12` 个别名（`ds-chat` … `grok`） |
| 注册 / 登录 | 建号成功，`/api/auth/login` 返回 JWT |
| 常驻内存 | 5 个容器合计 **600 MB** |

**踩到并修掉的 5 个坑**（都是原设计里的错误假设，文档已同步）

1. **`librechat-dev` 镜像没有静态服务器**。它的 CMD 是 `npm run backend`，产物在 `/app/client/dist`。原方案"挂载 index.html 到 `/usr/share/nginx/html`"完全落空 —— 改成抽出整个 dist，交给 caddy 托管，顺带删掉 client 容器。
2. **脚本用 `python`，Debian 只有 `python3`** —— 加 fallback。
3. **幂等判断写错**：镜像自带的 index.html 已经含 `manifest.webmanifest` 字样，导致"已注入，跳过"。改用自有标记 `umf-pwa-injected`。
4. **`version: 1.3.19` 高于镜像的 1.3.17**，触发告警 —— 对齐到 1.3.17。
5. **`fetch: true` + 无 Key = 模型列表清空** —— 改 `fetch: false` 用静态列表，且模型名必须和 `models.json` 的别名一致（原来写的 `glm-4.6`、`gpt-5`、`qwen-vl` 都不存在）。

**还没验的**：真实的 8 家模型对话。因为 `.env` 里还没填任何厂商 Key，`brain` 的 `/v1/models` 现在返回空数组 —— 这是设计好的行为（缺 Key 就跳过该别名），不是故障。
