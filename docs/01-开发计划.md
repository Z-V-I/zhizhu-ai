# UMF Chat · 开发计划 v1

> 目标：一个只对朋友开放的 AI 聊天站，PWA 可装到桌面/主屏；底座全部用开源，自己只写胶水层。
> 核心差异化：**一个大脑（Global Memory）· 多个智能体（人格/记忆边界）· 记忆可迁移（UMF 协议）**。

---

## 0. 结论先行（三句话）

1. **前端不要用 LobeChat。** 它已改名 LobeHub，许可证从 Apache-2.0 换成 **LobeHub Community License**——不修改源码可商用，但**修改后分发需要商业授权**。你要做的恰恰是大改（记忆、邀请码、UMF）。用 **LibreChat（MIT）**，随便 fork。
2. **核心不是"接一个记忆库"，而是在 LibreChat 和模型之间加一个 `Brain Gateway`。** 它伪装成 OpenAI 兼容接口，负责"检索记忆 → 注入 system prompt → 转发给 LiteLLM → 异步抽取新记忆"。这样 **LibreChat 一行核心代码都不用改**，就获得了全局记忆。
3. **UMF 自己定，Mem0 只做引擎。** 真相源（source of truth）放自己的 Postgres（`umf_*` 表），Mem0 当检索/抽取加速层。否则你的记忆资产就锁在别人的数据结构里，导出、时间线、迁移全都做不动。

## 2. 选型决策

### 2.1 前端：LibreChat（MIT）

| 候选 | 许可证 | PWA | 多模型 | Agent 自定义 | 改造成本 | 结论 |
|---|---|---|---|---|---|---|
| **LibreChat** | **MIT** | 需自己加（Vite 插件，简单） | 原生 + 任意 OpenAI 兼容端点 | Agents / Skills / Subagents / MCP | **低**（后端是 Express，加路由很自然） | ✅ **选定** |
| LobeChat / LobeHub | Community License（改后分发需商业授权） | 原生最好 | 强 | Agent Builder + Memory 很强 | 法务/成本风险 | ❌ 放弃（除非只当不改的壳） |
| Open WebUI | BSD-3 + 品牌条款（需复核） | 一般 | 强 | Pipelines/Functions 灵活 | 中（Python 后端，改起来其实舒服） | 🅱 备选 |

**为什么不是 Open WebUI**：它的 Pipelines 插件机制其实很适合做记忆中间层，如果你是 Python 舒适区，这是合理备选。但它的品牌条款、以及前端 Svelte 加自定义页面（记忆中心那种重交互页面）不如 React 生态顺手。LibreChat 赢在"MIT + Agents 数据模型现成 + 后端可插路由"。

### 2.2 记忆：Mem0 做引擎，UMF 做真相源

| 候选 | 定位 | 为什么不选/怎么用 |
|---|---|---|
| **Mem0**（Apache-2.0） | 事实抽取 + 混合检索 | ✅ **主引擎**。关键：作用域天然是 `user_id / agent_id / run_id / app_id` 四维，**这就是你要的"一个大脑多个智能体"**，不用自己发明隔离机制。支持 pgvector，不用额外引 Qdrant。 |
| Letta | 有状态 Agent，自管记忆 | ❌ 它会**抢走 Agent 循环的所有权**，和 LibreChat 的 Agent 层直接打架。放弃。 |
| Zep / Graphiti | 时序知识图谱（双时间轴） | 🅱 **二期可选**。Graphiti 的 `valid_at / invalid_at` 正好是"记忆时间线 + 观点变化"，但它要 Neo4j/FalkorDB，运维成本翻倍。v1 先用 UMF 表里的时间字段手搓时间线，够用。 |

> 注意：Zep 与 Graphiti 是相关但不同的项目，许可证与部署方式需分别核对（你自己也标注了这点，选型文档里保留这条）。

### 2.3 网关：LiteLLM Proxy

- 统一 OpenAI 兼容入口、模型路由、虚拟密钥、按用户额度、fallback、日志。
- **New API** 作为备选：如果你更看重"多渠道 + 额度 + 模型映射"的中文运营面板，它更顺手；但它偏"API 分发平台"，而 LiteLLM 偏"应用侧网关"，你这里选 LiteLLM 更对味。
- 部署位置：**海外 VPS（香港/新加坡/日本）**，LiteLLM 与 Brain Gateway 同机，出口直连 OpenAI/Anthropic。国内用户只访问你的域名，不碰被墙链路。

### 2.4 角色系统：不引入 Dify / LangGraph

理由：LibreChat 的 Agent 已经包含「系统提示词 + 模型 + 参数 + 工具/MCP + 文件」，覆盖你列的全部场景（温柔伙伴/技术顾问/哲学爱好者）。再引 Dify 等于多一套运维、多一套用户体系、多一套记忆，纯负收益。
**你真正要加的只有一层**：`Persona 包`（可导出的 JSON），把"角色描述 + 记忆权限 + 说话风格样例"打包，能一键复制给朋友、能随 UMF 一起导出。

## 3. 总体架构

```
                       ┌──────────────────────────────┐
   手机/桌面 PWA  ───►  │  Caddy（TLS + 反代 + 限流）    │
                       └───────┬──────────────┬───────┘
                               │ /            │ /api/umf/*  /umf-ui/*
                     ┌─────────▼────────┐   ┌─▼──────────────────────────┐
                     │  LibreChat       │   │  Brain Service (FastAPI)   │
                     │  web + api       │   │  ├ gateway  记忆注入/抽取   │
                     │  (MIT, fork)     │   │  ├ umf      UMF CRUD/导出   │
                     └──┬────────┬──────┘   │  ├ migrate  迁移引擎        │
                        │        │          │  ├ invite   邀请码          │
             Mongo ─────┘        │          │  └ timeline 时间线          │
            (会话/用户/Agent)     │          └───┬──────────────┬─────────┘
                                  │  OpenAI 兼容 │              │
                                  ▼              ▼              ▼
                        ┌──────────────────┐  Postgres     Mem0 SDK
                        │  Brain Gateway   │  + pgvector   （抽取/检索）
                        │  (假装是模型)     │   UMF 真相源
                        └────────┬─────────┘
                                 ▼
                        ┌──────────────────┐
                        │  LiteLLM Proxy   │ ──► OpenAI / Anthropic / DeepSeek / 国产
                        └──────────────────┘
```

**关键点：LibreChat 只把它当"一个自定义 OpenAI 端点"（叫 `Brain`）。**
好处：模型切换、流式输出、Agent、附件、搜索全部照旧；记忆逻辑 100% 在你自己代码里；哪天想换前端，Brain Gateway 原样复用。

### 3.1 一次对话的完整数据流

```
1. 用户在 LibreChat 选 Agent「技术顾问」，发一句话
2. LibreChat → POST /v1/chat/completions  (baseURL = Brain Gateway)
      headers: X-UMF-User / X-UMF-Agent   ← 由 fork 的一处小补丁注入
3. Brain Gateway：
   a. 读 UMF Profile 卡（常驻，≤400 tokens）
   b. Mem0.search(query, filters={user_id, OR agent_id}) 取 top-k
   c. 话题判定：是否延续当前 topic？→ 决定"轻量续接"还是"换话题重置"
   d. 组装 system = Agent 人格提示词 + 记忆块（自然语言化，禁止复述式输出）
   e. 转发给 LiteLLM，流式回传（SSE 透传，零缓冲）
4. 响应结束后（后台任务，不阻塞用户）：
   f. Mem0.add(最近 N 轮, user_id, agent_id)  → 抽取事实
   g. 抽取结果落 UMF：memories / entities / memory_events（带 valid_from）
   h. 冲突消解：新记忆 supersede 旧记忆 → 时间线自动长出"观点变化"
```

## 4. UMF 统一记忆协议 v1

### 4.1 设计原则

1. **人可读优先**：JSON 是给机器和开发者的，Markdown 是给"别的 AI"和用户自己看的。两形态必须信息等价。
2. **可追溯**：每条记忆都有 `source`（哪个平台、哪个会话、哪条消息）和 `confidence`。
3. **双时间**：`created_at`（记下来的时间）与 `valid_from/valid_to`（这件事在现实中成立的时间）分开。这是做时间线的唯一正确姿势。
4. **作用域最小化**：`scope = global | agent | topic`，默认 global，Agent 私有记忆必须显式声明。
5. **版本化**：`schema_version` 单调递增 + `migrations` 字段，永远能向上兼容。

### 4.2 结构（节选）

```jsonc
{

  "exported_at": "2026-11-19T10:12:00+08:00",
  "owner": { "umf_id": "u_8f3a...", "display_name": "阿泽" },

  "profile": {
    "basics":   [{ "k": "职业", "v": "后端工程师", "confidence": 0.95 }],
    "traits":   [{ "k": "沟通偏好", "v": "喜欢先结论后论证", "confidence": 0.8 }],
```

### 4.3 两条导出通道（你说的 A / B）

| 形态 | 文件 | 用途 |
|---|---|---|
| A. 标准结构 | `umf.json`（+ JSON Schema 发布） | 给开发者/其他平台适配，可作为平台间交换格式 |
| B. AI 可读 | `memory.md`（标题层级 + 自然语言） | 直接粘给任何模型当上下文；人也能读 |
| C. 原始会话 | `conversations.jsonl`（OpenAI messages 格式） | 完整聊天记录迁移，不丢细节 |

导出一个 `.zip`：`umf.json` + `memory.md` + `conversations/*.jsonl` + `README.txt`（说明字段）。**"平台不支持 UMF 就直接给 memory.md"——这是最实用的兼容策略。**

## 5. 一个大脑，多个智能体（记忆作用域）

### 5.1 作用域模型

| 层级 | 存储键 | 谁能读 | 例子 |
|---|---|---|---|
| **Global Profile** | `user_id` | 所有 Agent（可在 Agent 上关掉） | 名字、职业、沟通偏好、禁忌话题 |
| **Global Memory** | `user_id`，`scope=global` | 所有 Agent | 长期项目、重要人际关系、价值观 |
| **Agent Memory** | `user_id + agent_id` | 仅该 Agent | 技术顾问记得的架构决策；陪聊伙伴记得的情绪脉络 |
| **Session/Topic** | `user_id + agent_id + run_id` | 当前会话 | 本次讨论的临时结论 |
| **Topic Workspace** | `topic_id` | 授权该话题的 Agent | 「AI 聊天平台」项目下的全部上下文 |

写入策略：**抽取时同时写两级**——`agent` 级先写（细），再过一道"是否够通用"判定，够通用才升格到 `global`（粗）。这样既不会让技术顾问的细节污染陪聊人格，也不会让每个 Agent 都从零认识你。

### 5.2 记忆注入分层（决定"像不像老朋友"）

| 层 | 内容 | Token 预算 | 策略 |
|---|---|---|---|
| L0 常驻卡 | 结构化 profile 摘要 | ≤ 400 | 每轮都带，永不省略 |
| L1 相关记忆 | Mem0 top-k（按分数阈值+去重） | ≤ 600 | 与 L0 去重（语义级） |
| L2 话题工作区 | 当前 topic 的目标/进展/未决问题 | ≤ 300 | 话题切换时重建 |
| L3 会话滚动摘要 | 长对话压缩 | ≤ 300 | 超过 N 轮时触发 |

**“像朋友切换话题”的关键不在检索，在提示词纪律**：

```
记忆使用规则（硬约束）：
- 记忆是你的背景知识，不是台词。禁止输出"根据我的记忆""我记得你之前说过"。
- 用户换话题时直接接新话题，不要总结上文，不要问"我们刚才聊到哪了"。
- 只有当记忆能改变你的判断时才使用它；无关记忆一律不提。
- 不确定的记忆不要断言，用"你之前好像提过…"这种自然口气。
```

再加一条产品级细节：**"刚想起来"机制**——如果检索到的记忆相关性极高但本轮没被用到，允许在回复末尾自然带一句（每 5 轮最多 1 次）。这是"懂你"的体感来源，但不能滥用。

### 5.3 冲突消解（时间线的原材料）

新记忆入库时三选一：`ADD` / `UPDATE`（同一事实更新，旧的置 `valid_to`）/ `NOOP`（已存在）。
Mem0 自带一轮去重，但**判定权在 UMF 层**：只有 UMF 落库成功并写了 `supersedes`，"观点变化"才会出现在时间线上。

## 6. 角色系统（Persona 包）

```jsonc
{
  "persona_id": "p_tech_advisor",
  "name": "老陈 · 技术顾问",
  "avatar": "emoji:🧰",
  "tagline": "先给结论，再给理由，最后给风险",
  "system_prompt": "你是一位资深后端架构师……（用户自由书写）",
  "style": { "tone": "克制", "length": "中", "examples": ["…用户满意的回答样例…"] },
  "memory_policy": {
    "read_global_profile": true,
    "read_global_memory": true,
    "read_agent_memory": true,
    "write_scope": "agent",          // agent | global_both
    "allow_promote_to_global": true  // 抽取时可升格
  },
  "model_defaults": { "model": "gpt-5", "temperature": 0.6 },
  "tools": ["mcp:filesystem", "web_search"]
}
```

落地方式：`brain` 服务存 Persona，创建/编辑时通过 LibreChat 的 Agents 接口同步一份（LibreChat 的 Agent 负责真正执行），Persona 只做"可导出、可分享、带记忆策略"的外壳。
**朋友之间互传人格** = 发一个 `persona.json` + 可选 `umf-subset.json`（只带这个话题的记忆），这是很自然的传播点。

## 7. 网关与多模型

### 7.1 免翻墙访问 GPT 的三条路（按推荐度）

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **A. 自建海外 VPS + LiteLLM**（推荐） | 港/新/日 VPS，LiteLLM 直连官方 API | 稳定、可控、可审计、额度自己管 | 需运维；需合规自查 |
| B. Cloudflare Worker 反代 | 无服务器中转，成本近零 | 便宜、部署快 | 流式/长请求易被限制，排障难 |
| C. 第三方中转 API | 直接买中转 Key | 零运维 | 稳定性/隐私/合规都在别人手上，**不推荐存记忆数据** |

> 合规提示（简述，不展开）：只给熟人小范围使用、不公开推广不收费，与"面向公众提供生成式 AI 服务"是两种性质；一旦要公开注册/收费，需先处理备案与内容安全义务。这条在 v1 就写进 README，避免以后返工。

### 7.2 LiteLLM 关键配置要点

```yaml
model_list:
  - model_name: gpt-5            # 前端看到的名字
    litellm_params: { model: openai/gpt-5, api_key: os.environ/OPENAI_KEY }
  - model_name: claude-sonnet
    litellm_params: { model: anthropic/claude-sonnet-4-5, api_key: os.environ/ANTHROPIC_KEY }
  - model_name: cheap-extract    # 专供记忆抽取，省钱
    litellm_params: { model: deepseek/deepseek-chat, api_key: os.environ/DEEPSEEK_KEY }

router_settings:
  fallbacks: [{ "gpt-5": ["claude-sonnet"] }]
  num_retries: 2
  timeout: 600
litellm_settings:
  drop_params: true              # 不同厂商参数不兼容时自动丢弃
```

- **虚拟密钥**：每个用户一把 `sk-umf-xxx`，绑 `max_budget`；Brain Gateway 用它转发，用户永远看不到真实 Key。
- **抽取用便宜模型**：记忆抽取量是聊天量的 2-5 倍 token，必须单独走 `cheap-extract`，否则成本失控。

|---|---|

## 9. 迁移引擎（AI 记忆迁移中心）

### 9.1 流水线

```
上传(ZIP/JSON/TXT/MD/HTML)
   → 格式识别 & 解析器选择
   → 归一化：Conversation IR（role/content/ts/conv_id）
   → 话题聚类（embedding + LLM 归档）
   → 抽取：facts / preferences / relations / events(带时间)
   → 生成 UMF 草稿（draft，不落正式库）
   → 【人工确认 UI】逐类确认/编辑/删除/合并
   → 提交：写 Mem0（带 metadata）+ 写 UMF 正式表 + 记 import_batch
   → 报告：新增 N 条、冲突 M 条、跳过 K 条
```

### 9.2 解析器矩阵（v1 只做 4 个，其余走通用兜底）

| 来源 | 输入形态 | 解析要点 |
|---|---|---|
| ChatGPT | `conversations.json`（mapping 树） | 树 → 按 `create_time` 线性化；跳过 `tool` 节点 |
| Claude | `conversations.json` | `chat_messages` 数组，字段名不同 |
| DeepSeek | 导出 JSON/HTML | HTML 情况下用 cheerio 抽气泡 |
| 豆包 | TXT/MD/JSON（视版本） | 若只有纯文本：按"我/你"说话人标记 + 时间戳切分，缺失则整段交给 LLM 归纳 |
| 通用 | 任意 TXT/MD | 直接 LLM 归纳（质量降级但可用） |

### 9.3 三个必须做对的工程点

1. **幂等**：`hash(conv_id + msg_id + text)` 落 `import_items`，重复导入不重复计数（否则朋友重跑一次就变成双份记忆）。
2. **可回滚**：一次导入 = 一个 `import_batch`，支持"撤销这批"，物理删除其写入的 memory + Mem0 记录。
3. **不阻塞**：迁移是长任务，走 Redis 队列 + 进度条；前端轮询 `/api/umf/imports/{id}`。

### 9.4 双向

- **导入**：上面这套。
- **导出**：§4.3 三种形态；额外给「只导出某话题/某人格的记忆子集」。
- **互通**：`memory.md` 就是万能格式——任何不认识 UMF 的平台，把这份 Markdown 塞进它的"自定义指令/记忆"就能用。

## 11. 数据模型（Postgres）

```sql
-- UMF 真相源
users_mirror   (id PK, librechat_user_id UNIQUE, umf_id, display_name, created_at)
umf_profiles   (user_id PK, data JSONB, version INT, updated_at)
memories       (id PK, user_id, scope, agent_id NULL, topic_id NULL, kind, text,
                embedding vector(1536), entities JSONB, valid_from, valid_to,
                supersedes_id, source JSONB, confidence, import_batch NULL,
                created_at, deleted_at)
entities       (id PK, user_id, name, type, attrs JSONB)
relations      (id PK, user_id, from_id, rel, to_id, since, until, confidence)
topics         (id PK, user_id, title, status, started_at, summary)
memory_events  (id PK, user_id, at, type, ref_id, summary)   -- 时间线直接查这张
personas       (id PK, user_id, name, data JSONB, librechat_agent_id, is_public)
invite_codes   (code PK, created_by, max_uses, used_count, expires_at, note, disabled)
import_batches (id PK, user_id, source_platform, file_name, status, stats JSONB, created_at)
import_items   (id PK, batch_id, content_hash UNIQUE, conv_id, msg_id, action)
audit_log      (id PK, user_id, action, target, meta JSONB, at)
```

`memories.embedding` 同时给 Mem0 用（pgvector），避免再维护一套向量库。

## 12. 部署（单机 docker compose）

| 服务 | 端口 | 说明 | 内存建议 |
|---|---|---|---|
| caddy | 80/443 | TLS、反代、`/api/umf`、`/umf-ui`、限流 | 128M |
| librechat | 3080 | api + client | 1G |
| mongodb | 27017 | 会话/用户/Agent | 1G |
| meilisearch | 7700 | 消息搜索 | 512M |
| redis | 6379 | 缓存 + 队列 | 256M |
| brain | 8000 | FastAPI：gateway/umf/migrate/invite/timeline | 512M |
| brain-worker | - | RQ/Celery：抽取、迁移 | 512M |
| postgres(pgvector) | 5432 | UMF + Mem0 向量 | 1G |
| litellm | 4000 | 模型网关 | 512M |

- 机器：**4C8G 海外 VPS** 起步（¥150–300/月），磁盘 80G。
- 备份：Postgres `pg_dump` 每日 + Mongo `mongodump` 每日，推对象存储（R2/B2），保留 14 天。**记忆是你的核心资产，备份优先级高于一切。**
- 监控：Uptime Kuma（存活）+ LiteLLM 自带花费日志；简单 Grafana 可选。
- 迁移引擎 worker 单并发，防止把 API 额度打爆。

## 13. 里程碑

### M0 · 骨架跑通（3–5 天）
- compose 起全栈；LibreChat 能通过 `Brain` 端点 → LiteLLM → 真实模型对话。
- PWA 可安装到手机主屏，离线打开有壳。
- **验收**：手机主屏图标打开、发消息有流式回复；关掉 WiFi 显示离线页。

### M1 · 准入与基础体验（4–6 天）
- 邀请码注册、按用户虚拟 Key + 额度、模型切换器、会话历史/搜索正常。
- **验收**：陌生人无码进不来；两个朋友各自的会话互不可见；切换 3 个模型上下文不丢。

### M2 · 记忆核心（10–14 天，最重）
- Brain Gateway：注入 + 抽取 + 冲突消解；UMF 表与 Mem0 双写；记忆中心 UI（列表/搜索/编辑/删除/按作用域过滤）；时间线 v1。
- **验收**：新会话里问"我上次说的那个项目进展"能答对；删除某条记忆后下一轮不再出现；时间线能看到"兴趣变化"节点。

### M3 · 迁移与导出（8–12 天）
- ChatGPT / Claude / DeepSeek / 豆包解析器；草稿确认 UI；批量回滚；UMF JSON + memory.md + 会话导出。
- **验收**：导入 500 条 ChatGPT 会话 < 10 分钟完成；重复导入不产生重复记忆；导出的 memory.md 塞进第三方模型能正确回答"我是谁"。

### M4 · 人格与打磨（7–10 天）
- Persona 包（创建/导出/导入/分享）；Agent 记忆权限三开关；移动端细节；备份/监控/错误页；内测邀请 5 人。
- **验收**：朋友收到 `persona.json` 能一键建成同样人格；技术顾问与陪聊人格记忆不串味。

**总计 5–7 周**（一个人、每天 3–4 小时的有效投入）。

## 16. 需要你拍板的 5 件事

1. **前端定 LibreChat 吗？**（若你更爱 LobeHub 的 UI 且愿意接受"不改源码"或买授权，方案要重写记忆层接入方式）
